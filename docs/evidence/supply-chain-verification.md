## Independent check from the workstation

The blocks above were produced on a GitHub runner. This one was not: it was run
from the Windows workstation against **public Rekor**, which needs no registry
credentials. It confirms the same transparency-log entries exist and that the
Fulcio certificate binds them to the identity the policy pins.

The registry itself could not be read locally — the workstation's `gh` token has
no `read:packages` scope, so `cosign verify` against GHCR fails there. See
[BLOCKED.md](../BLOCKED.md).

The SAN is exactly the `--certificate-identity` the pipeline pins, and extension
`1.3.6.1.4.1.57264.1.8` is exactly the `--certificate-oidc-issuer`. Those two
strings together are the entire trust anchor of a keyless setup: identity alone
would be forgeable by any other issuer Fulcio accepts, issuer alone is every
GitHub Actions workflow in existence.

## What a reader should take from this

- The signature and both attestations are bound to the **digest**, never a tag.
- The verification pins identity **and** issuer, and fails closed.
- The negative control shows the verifier refusing an artifact it never signed —
  without it, a green run only proves the happy path.
- Nothing here yet proves a **cluster** refuses an unsigned image. That is the
  admission-control half, and it is not built. See the roadmap in the README.
