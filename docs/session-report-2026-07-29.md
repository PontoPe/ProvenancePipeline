## Decisions taken on your behalf

Full reasoning in [architecture.md](architecture.md); the short version:

| ADR | Decision | Why |
|-----|----------|-----|
| 001 | Stdlib-only Go service, no third-party modules | A 7-package SBOM means any CRITICAL is real, which is what makes a hard-fail gate survivable |
| 002 | `golang:1.26-alpine` → `distroless/static-debian12:nonroot`, both pinned by digest | Refusing mutable tags at admission while building on one is not a coherent position |
| 003 | Gate at CRITICAL, hard-fail, no allowlist | HIGH-and-above converts into permanent allowlisting or a disabled gate |
| 004 | `provenance: false`, `sbom: false` on buildx | Keeps one subject per index so the signed digest is unambiguous, and avoids shipping an unsigned provenance alongside a signed one |
| 005 | SLSA provenance attested **twice** | Kyverno speaks cosign, not `gh`. The cosign copy is the one a cluster can enforce |
| 006 | Negative control in the verify job | A verifier that never says no is not a verifier |
| 007 | Evidence generated by CI, not hand-written | Hand-copied evidence goes stale silently |

Two judgement calls worth flagging explicitly:

- **I did not touch GHCR package visibility.** You made the repo public
  mid-session; the package is still private and that stays your call. It is the
  reason local `cosign verify` fails (B1).
- **Keyless signing publishes the repository identity to a public log.** The
  Fulcio certificates in Rekor contain
  `https://github.com/PontoPe/ProvenancePipeline/.github/workflows/release.yml@refs/heads/main`
  in plaintext, and Rekor is append-only and world-readable. This was already
  true when the repo was private. It is inherent to the keyless decision, not a
  regression, but it is worth knowing that signing a private repo's artifacts
  discloses the repo's existence and name.

## What broke, and what it taught

**`actions/attest-build-provenance` refuses user-owned private repos.**

```
Failed to persist attestation: Feature not available for user-owned private
repositories. To enable this feature, please make this repository public.
```

This is the failure that produced the most useful design change. Chasing it
surfaced the real point: even where GitHub's attestation works, Kyverno cannot
verify it — Kyverno verifies through cosign and Sigstore, and has no way to
call `gh attestation verify`. So the pipeline now produces its own SLSA v1
predicate signed with cosign into public Rekor. That attestation is the one the
future admission policy will actually pin. Had the repo been public from the
start, I would probably have shipped a provenance the cluster could never
enforce and not noticed.

**cosign v3 changed the signature envelope format.** Two dead ends: the inlined
`Bundle` is now null, and `cosign download signature` emits Sigstore bundles
(`mediaType` / `verificationMaterial` / `dsseEnvelope`), not the legacy
`{Payload, Bundle}` shape. I guessed the field name twice and got silently
empty results both times, which is the lesson — the jq expressions failed to
*nothing*, not to an error. The fix reads `verificationMaterial.tlogEntries[]`
directly from the bundle, which is both correct and drops a Rekor API
round-trip. The step now logs the envelope keys so the next format change is
visible instead of silent.

**cosign writes its checklist to stderr and its payload to stdout.** Folding
them together with `2>&1` fed prose into `jq`, and the `|| true` I had added
swallowed the failure, so the first generated evidence file had two empty
sections. Caught only because I read the artifact instead of trusting the green
check. Defensive `|| true` hid a real bug — worth remembering.

**`go test -race` needs cgo**, which this workstation has no C toolchain for.
`make test` failed until the flag was made conditional on the platform. CI still
runs with `-race`.

### Scaffolding bugs found in the pre-existing files

These were in the repo before this session and would each have broken the first
real run:

- **`env: IMAGE: ghcr.io/${{ github.repository }}`** — `github.repository`
  preserves owner casing, so this yielded `ghcr.io/PontoPe/...`. GHCR rejects
  uppercase path segments. Now folded to lowercase in a `meta` step.
- **`context: build`** in the build step. The Dockerfile lives in `build/` but
  the application source is in `app/`, so the build context would not have
  contained the code. Context is now the repo root with an explicit `file:`.
- **Actions pinned by tag** (`actions/checkout@v4`, `cosign-installer@v3`,
  and so on) — directly contradicting the convention in `AGENTS.md`, in the repo
  whose whole argument is that mutable references are the problem. All now
  pinned by commit SHA.
- **`cosign triangulate --type digest $(REF)`** in the Makefile's `sign` target.
  `triangulate` returns the *signature tag*, not the image digest, so signing
  would have targeted the wrong object.
- **The verify job used `--certificate-identity-regexp
  "^https://github.com/${{ github.repository }}/"`.** That prefix matches *any*
  workflow in the repository, so a signature from an unrelated workflow would
  have passed. Replaced with the exact identity, computed once and threaded
  through as a job output so CI, the Makefile and the future policy all pin the
  same string.

## SLSA level, honestly

**Build L2. Not L3.**

L2 is met: a hosted build platform, provenance signed with the workflow's own
OIDC identity through Fulcio, entries in public Rekor, and a consumer-side check
that pins identity and issuer and fails closed.

L3 is not, and the gap is real rather than paperwork. L3 requires the provenance
to be unforgeable by the build process itself — generated in an isolated context
the workflow's steps cannot influence. Here the predicate is assembled by a
`jq` step in the same job that builds the image. Anything that compromises that
job can write whatever provenance it wants and it will be signed. Closing it
means delegating to `slsa-framework/slsa-github-generator`, which runs the
generation in a separate reusable workflow with its own identity.

Also worth stating plainly: provenance proves *where* an artifact came from. It
never proves the source was benign. That is T3 in the threat model and no amount
of SLSA level changes it.
