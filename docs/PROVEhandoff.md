## 1. What this project is

A software supply-chain pipeline: build → SBOM → vulnerability scan → keyless
signature → SLSA provenance attestation → **admission control that refuses
anything unsigned**.

Portfolio artifact for cloud-security roles, positioned as the CKA→CKS bridge.

**The deliverable is the rejection, not the pipeline.** Anyone can show a green
CI run. The recorded demo where a cluster refuses an unsigned image is the thing
few junior candidates have. Keep that framing when deciding what to work on —
it is the tiebreaker for every scope question below.

Owner: Pedro (GitHub `PontoPe`). Repo `github.com/PontoPe/ProvenancePipeline`,
**public** as of 2026-07-29. The GHCR package is **public** too, verified
2026-07-30 (`gh api user/packages/container/provenancepipeline --jq .visibility`).
That resolved B1 and it is also what B5 is about — enforcement currently depends
on it staying that way.

## 3. The one string everything pins

Keyless signing has no key. This pair **is** the trust anchor:

```
identity: https://github.com/PontoPe/ProvenancePipeline/.github/workflows/release.yml@refs/heads/main
issuer:   https://token.actions.githubusercontent.com
```

Pin **both**, always. Identity alone is forgeable by any other OIDC issuer
Fulcio accepts. Issuer alone matches every GitHub Actions workflow in existence.

The workflow computes this once in the `meta` step and threads it through as a
job output, so CI, the `Makefile` and the future Kyverno policy all reference
one source. Do not hand-copy it into a fourth place — derive it.

Do not replace it with `--certificate-identity-regexp` anchored on the repo
prefix. That was in the original scaffold and it accepts a signature from *any*
workflow in the repository.

Both halves of the pair were shown to be load-bearing rather than assumed to be:
substituting a different workflow in the same repository turns an admitted pod
into a denied one, and so does substituting a different OIDC issuer. Recorded in
`docs/PROGRESS.md` step 2.

**The attestation the cluster enforces is GitHub's, not cosign's.** GHCR's
referrers API answers 404; the tag-fallback index carries `artifactType` only on
GitHub's descriptor, and Kyverno filters on precisely that, so of the four
Sigstore bundles on each image it can discover exactly one. Pinning cosign's
`buildType` was tested and **denies every image**. Do not "fix" the policy that
way. The policy therefore pins `runDetails.builder.id` and the workflow
repository and ref — identical in both provenance documents — and deliberately
does not pin `buildType`. ADR-009.

## 5. Next steps, in order

Everything the original scope asked for is done. What remains is one real
weakness and two improvements.

1. **Break the dependency on repository visibility (B5).** This is the only item
   that affects whether enforcement keeps working. `actions/attest-build-provenance`
   writes the one bundle Kyverno can see, and `release.yml:220` gates it on
   `if: steps.meta.outputs.private != 'true'`. Make the repo private and every
   new image is denied at admission. Fix by pinning **cosign 2.x** in CI: 2.x
   defaults to the legacy `.sig`/`.att` layout, which Kyverno reads through its
   default `type: Cosign` path with no referrers API involved, restoring
   ADR-005's original intent. Check the flags against `cosign sign --help` for
   the chosen version — 3.1.2 has no `--new-bundle-format`, that was verified.
2. **Report the cosign referrers-index bug upstream.** cosign writes the
   fallback-tag index with `artifactType` set to the config media type instead of
   the manifest's own, which makes its bundles invisible to any consumer using
   `remote.Referrers`. GitHub's writer gets it right in the same index, so one
   artifact demonstrates both behaviours.
3. **Scheduled re-scan of published digests.** Base images are digest-pinned and
   therefore static, so a new CVE against a shipped image surfaces only on a
   rebuild. A scheduled `grype` run against the published digest closes that.

Housekeeping: consider `kubectl wait` instead of the `sleep 6` in
`scripts/demo.sh`.

## 7. Decisions that are settled — do not relitigate

From `AGENTS.md`, still binding: keyless signing (no key pair), Kyverno over
Gatekeeper, `Enforce` + `failurePolicy: Fail`, GHCR, digests pinned and tags
never trusted, `grype` gate at CRITICAL.

Added this session, reasoning in [architecture.md](architecture.md):

| ADR | Decision |
|-----|----------|
| 001 | Stdlib-only Go workload — small SBOM means any CRITICAL is real signal |
| 002 | Digest-pinned `golang:1.26-alpine` → `distroless/static-debian12:nonroot` |
| 003 | Gate at CRITICAL, hard-fail, no allowlist, no soft-fail |
| 004 | `provenance: false`, `sbom: false` on buildx — one subject per index |
| 005 | SLSA provenance attested twice; the cosign copy is what the cluster enforces |
| 006 | Negative control in the verify job |
| 007 | Evidence generated by CI, never hand-written |
| 008 | Kyverno's NetworkPolicy ships here, not in KateClusters |
| 009 | **The cluster enforces GitHub's provenance, not cosign's** — corrects ADR-005 |
| 010 | The enforcement plane is installed with the integrity this repo demands elsewhere |

**The gate is not negotiable.** No `continue-on-error`, no `soft_fail`, no
raised threshold, no ignore file. If a CRITICAL appears, move the base image or
update the dependency. A gate switched off to make a run green is worse than no
gate, because it also lies — and this repo is sold on exactly that claim.

## 8. Honest limitations

State these plainly; overstating is worse than a lower number.

- **SLSA Build L2, verified at admission — not L3.** The second half is worth
  saying because SLSA levels describe how an artifact is *produced* and say
  nothing about anyone checking it before running it. Enforcing at admission
  does not raise the level; it is what makes the level mean anything
  operationally. Do not round this up to "L3" or to "SLSA compliant".
- **SLSA Build L2, not L3.** The provenance predicate is assembled by a step in
  the same job that builds the image, so anything compromising that job can
  write its own provenance and have it signed. L3 requires delegating to
  `slsa-framework/slsa-github-generator`, which generates in an isolated context.
- **Provenance proves *where*, never that the source was benign.** T3 in the
  threat model. No SLSA level changes this.
- **MEDIUM and HIGH vulnerabilities ship.** Deliberate, documented in T2.
- **Enforcement is opt-in per namespace for third-party images.** The rule that
  denies *any* unsigned image applies only to namespaces labelled
  `provenancepipeline.io/admission: enforced`. Cluster-wide would deny the
  KateClusters workloads this cluster runs, on their next restart. The rule
  covering this repo's own images is cluster-wide, minus four enumerated
  platform namespaces.
- **Enforcement depends on a GitHub feature flag.** B5. This is the largest
  structural weakness in the design as it stands.
- **Admission control is not a sandbox.** It decides what may start. It says
  nothing about what a container does once running — that is Falco's job on this
  cluster, and it belongs to the sibling repo.
- **Keyless signing publishes the repo identity to a public log.** The Fulcio
  certs in Rekor contain the full workflow URL in plaintext, and Rekor is
  append-only and world-readable. Inherent to the keyless decision, and it was
  true while the repo was still private.
- **No Rekor monitoring.** T7 has no automation behind it.

## 9. Environment gotchas

Windows 11, PowerShell 7. These cost time already:

- `winget install Sigstore.Cosign` does **not** create a `cosign` shim — it
  drops `cosign-windows-amd64.exe` in
  `%LOCALAPPDATA%\Microsoft\WinGet\Packages\Sigstore.Cosign_*\`. Copied to
  `~/bin/cosign.exe`; same for syft and grype.
- `winget install GnuWin32.Make` fails unattended with `0x800704c7` (a UAC
  prompt). `scoop install make` works without admin.
- `go test -race` fails here: `-race requires cgo`, no C toolchain. The Makefile
  disables it on Windows via `ifeq ($(OS),Windows_NT)`; CI still runs with it.
- Makefiles assume POSIX. Run from Git Bash or WSL.
- PowerShell `&&` short-circuits; `winget install` takes one package per call;
  new terminal needed after install for `PATH`.
- Installed and working: docker (daemon flaky, see B2), kubectl, terraform
  1.15.8, trivy 0.72.0, cosign 3.1.2, syft 1.49.0, grype 0.116.0, make 4.4.1,
  Go 1.26.1, gh 2.89.0.

## 10. Working agreements

- Conventional Commits, author `heavensnipe@gmail.com`. Working directly on
  `main` is fine in this repo.

  itself have an unpinned supply chain. Resolve with
  `gh api repos/OWNER/REPO/git/ref/tags/vX.Y.Z --jq .object.sha`.
